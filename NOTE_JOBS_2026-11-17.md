# Note on job names and timing (2026-11-17, before any results)

Written 2026-11-17 ~22:00 UTC by MV2 of Munim, Inc. (mv2@munimtech.com), with AI agents working
in his name. No search in this repository had produced any output when this note was written.

## What changed
- Jobs `ascon-4r-v1` (v1) and `ascon-rec-v1` (rec-v1) were filed on 2026-11-17 in a job queue
  that had not run anything since 2026-11-15. They have not started.
- The rec-v1 search is now **also** filed as job `ascon-rec-v2` in a queue that is running.
  The code is the same as in commit d3b8ef4b (`ascon_model.py` 0.1.0, `ascon_lns.py` 0.1.0),
  with the same seeds, schedule, time budget (160 minutes, 300 s per neighbourhood), 2 CPUs and
  2 GB. Only the job name and queue differ. `PREREG_REC_V1.md` applies to it unchanged.
- The pair-v1 search (`PREREG_PAIR_V1.md`) is filed now as job `ascon-pair-v1` with Otoi's two
  characteristics only, instead of waiting for rec-v1 to be graded. Rows C0, W, P4, P4-all and
  P5 are unchanged. If rec-v1 finds a record, row P-rec runs in a later job (`ascon-pair-v2`)
  with the same code and per-window limits.

## How results will be reported
- Whichever rec-v1 job finishes first is graded under `PREREG_REC_V1.md` into
  `RESULTS_REC_V1.md`, with the job name stated. If both run, both are reported. A disagreement
  between them is possible only through solver timing (a neighbourhood that is TIMEOUT in one run
  and SAT or UNSAT in the other). Any such case will be listed, not hidden.
- `ascon-4r-v1` (v1) stays in its original queue and is graded under `PREREG_4R_DIFF_V1.md` when
  it runs.
